## Piano Transcription so far 

So far in this project, what we have done is enable the user to upload a given audio file, and then, given some algorithms that we have from ByteDance, we detected the pitches and the key strokes from the piano and how long they will be held. This approach has led to many errors because this algorithm is far from perfect. There are a lot of false positive notes: when pitches are high, they are not properly detected, or when there is some pedal, it gets very mixed. There is a need whenever we use some piano. Audio files coming from a YouTube video that is coming from this kind of Synthesia like piano roll animations. We can either edit the video and see it frame by frame, but not frame by frame. You can sample maybe 10 frames per second, the idea is that we will infer what note is struck every time, thanks to the notes falling approach. In the visuals of the video, we will see some notes falling from the sky. We will need to understand now which is the translation into the piano key strokes.

This will lead us into a first text file in which we will have, in a simplified notation at every timestamp, what keys that are "onsets" and then which keys are still sounding (sustained). This piano notation tends to use rectangles, vertically falling from the sky. The problem with these rectangles is that some of them are shallow, some of them have some solid background, and some of them have the background is shiny or there is a color gradient, some notes when they are pressed emit some light, some of this light (or called "halo" or "light") sometimes is a bit coarse so we should take some kind of the middle point of this halo to see the note, some notes after they are released emit some kind of "sparks" / "sparkles" (which are light little shining small particles), some of them ar simply solid, the colors of the rectangles may vary (some use the rectangles colors to mark Left Hand and Right Hand, some do not differentiate them, I don't want to infer the hands by the colors, this app has already a way to divide hands).

## Phase 4. Piano Matrix Notation

Once we have the piano video very well calibrated, with the overlay well calibrated and all the time frames matching perfectly, what we can do is then work on the transcription of the piano rectangles into the kind of piano matrix notation that we are operating with before we convert it into an HTML rendering of the piano sheet. In principle, this will be a matter of you trying to understand how to transform the coordinates of the rectangles that we have inferred (the offsets and so on of a given frame) into this notation: to understand when a note has been offset, when it has been sustained, and when it is not sounding anymore. This will be kind of simple if we have the coordinates of the rectangles for every time frame and we have this way of attributing a given onset and a given release of a note to each time frame.

It is important to notice that in this step we do the separation now between left hand and right hand. It is very important that we provide a first format for the notes that are sounding, getting released, or getting sustained, so that we can then run the same algorithm for the piano hand separation. We can then later have the final piano matrix notation in both hands separated, which is the one that helps then produce the piano sheet in the HTML render
