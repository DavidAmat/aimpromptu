# 1. P8.4 — the sheet's buttons follow you down the page

Task: **P8.4, new.** Not in `plan.md`. Asked for directly: *"I want this menu of buttons to be
floating so that we can save the metadata changes without having to scroll up again."*

## 1.1 Why this was needed

Every decision a reader makes about a piece is made somewhere in the middle of the sheet — a key
change on the third system, a fingering on the ninth — and the only button that keeps any of it sat
at the very bottom of the page. On a long piece that is a scroll past every stave to press **Save**
and a scroll back to find where you were. There was also no way at all to start over: the reading
saved with the piece could be replaced but never removed, so a piece read wrongly stayed read
wrongly.

## 1.2 What was built

`aitu-frontend/src/components/common/FloatingBar.tsx` — new. A row of controls fixed over the page,
dragged by a grip, clamped to the window and kept on screen when the window is resized. Hiding it
leaves a small round button in the same place, which brings it back where it was left. Deliberately
not a `ToolboxDialog`: no title bar, no panel, nothing to read, and it sits at `z-index` 1200 so a
toolbox always opens in front of it.

`aitu-frontend/src/pages/playground/RhythmPage.tsx` — the bar itself, rendered from **The sheet**
and so on screen only once there is a sheet. Three controls:

- **play / pause**, driving the same transport as the player at the top of the sheet.
- **Save**, the same call as *Save this rhythm with the piece*. The button says `Saved` in green for
  2.6 s afterwards, because the note that used to say so is now several screens away.
- **Remove all**, new. Clears the key signature and its changes, the speed changes, the renamed
  figures, the beam breaks, the octave brackets, the hidden notes, the hand moves and every
  fingering, then `DELETE /time/{id}/rhythm` and redraws. Two presses — the first arms it and it
  disarms itself after 5 s or when anything else on the bar is pressed.

`aitu-frontend/src/components/time/ScorePlayer.tsx` — a new `onPlaying` prop. `controls.toggle` was
enough to start and stop the recording from elsewhere but not to *draw* a button that says which of
the two it will do, because a ref re-renders nothing.

## 1.3 Decisions taken inside the task

**The wipe goes to disk as well as to the screen.** Clearing only the state would look identical and
be undone by the next visit — a button that appears to work. `forgetRhythm` already existed in
`api/timeScore.ts` and had never been called from anywhere.

**The named gap survives it.** *Remove all* is "unmark this piece", not "unread it": the sheet stays
drawn from whichever pile was named, because starting the reading over is what the plot at the top
of the page is for.

**The octave brackets need clearing twice.** They are seeded from what the register suggests the
first time a piece is drawn, so clearing the list alone would put every one of them straight back on
the next redraw (D38). `decidedOttavasFor` is set to the "somebody has decided" sentinel as part of
the wipe.

**`apply` takes the speed changes as an argument.** The wipe calls it in the same tick as
`setStretches([])`, so the closure still holds the changes it just threw away and would have redrawn
the sheet it was asked to undo.

## 1.4 Things believed that turned out false

That the wipe could reuse the page's existing *Remove all changes* button, which only clears the
speed changes. Everything else — figures, beams, brackets, hidden notes, hands, fingers — had no way
back at all short of reloading the tab, and reloading brought the saved reading with it.

## 1.5 Tests

No unit tests. Verified by running the frontend against a stub `/time` backend in a Linux container
and driving Chromium: the sheet draws, the bar stays put through a 1600 px scroll, drags to the
middle of the page, arms and disarms, saves (`GET /rhythm` → 200), wipes (`GET /rhythm` → 404 and
the key signature back to C with the sheet redrawn), hides to its button and comes back where it was
left, and its play button toggles with the player above it. No console errors.

`npx tsc -b` clean. `npx eslint src` reports only the pre-existing `controls.current` immutability
error in `ScorePlayer.tsx`. `npm run check:render` was already failing before this task on a 1.x
fixture and is untouched by it.

## 1.6 Left open

The bar carries the two actions that were asked for plus transport. **Write the sheet** is still only
reachable at the top of the page, so a speed change added halfway down still needs a scroll to draw.
