# P4.4, P4.6, P4.7 and P4.8 — the last of the old model leaves the repository

Tasks: P4.4, P4.6, P4.7, P4.8 `[AITU]`. Decisions implemented: D-01, D-14, D-30.
Date: 2026-08-07. Status: done, checked on screen. Phase 4 is complete.

## 1. Why these four went together

They are one idea seen in four places. After P4.2 the running code no longer used a tempo or a
granularity, but three things still spoke that language: the names of the folders artifacts are
saved in, the portable text format, and a module whose whole purpose was to make playing fit a beat
grid. None of them affected what the app did, and all three would have taught the next reader a model
that no longer exists.

P4.8 is the check that the four together left the suite green.

## 2. P4.4 — the version-folder scheme

### 2.1 The choice

A saved folder was `v2_gsc`: a version number plus a granularity code, the note figure one column
stood for. There are no granularities any more, so the code had to be replaced with something, and
the plan left the choice open between dropping it (`v2`) and putting the frame length in its place
(`v2_f40`).

**The scheme is `v2_f40`**, and the reason is an idea the repository is built on and which survives
the refactor untouched: *a version is a musical state, and the grid is a view of it*. `v1_gsc` and
`v1_gn` were the same take collapsed two ways, which is why saving at a second granularity pinned the
version number instead of advancing it. The same is true of a wall clock: the same recording at 20
and at 40 ms is the same playing on a finer or a coarser grid. Dropping the suffix would make two
views of one state collide on one folder name, and would lose a distinction the code already knows
how to keep.

The suffix is the frame length in milliseconds, so `v2_f40` reads directly as "version 2, forty
milliseconds a column". A fractional frame length writes with the point removed, `f12_5` for 12.5 ms,
because a dot in a folder name invites a reader to treat what follows as an extension.

Recorded in `contract.md` §8, which P4.4 asked for.

### 2.2 What happens to a folder written under the old scheme

It is **refused, not guessed at**. `parse_version_folder("v2_gn")` raises, and `next_version` skips
what it cannot parse, so a stray old folder can neither be silently reinterpreted nor block a save.
That matches P4.5's rule and the same reasoning: `gsc` meant "semicorchea", whose length came from a
tempo nobody wrote down, so there is no honest frame length to convert it to. P4.1 found no such
folder on disk, so nothing is stranded by this.

### 2.3 Files

`schemas/naming.py` loses `granularity_code` and `granularity_from_code` and gains `frame_code` and
`frame_from_code`; `version_folder` and `matrix_filename` take a frame length.
`storage/paths.py` follows. `schemas/metadata.py`: `VersionMetadata` and `VersionHistoryEntry` carry
`frameMs` instead of `tempoBpm` + `granularity` + `timeStepSeconds`. `storage/repository.py` reads
the frame length off the matrix. `matrix/model.py` gains `time_based_from_coo`, the pair to
`time_based`, so a stored wall-clock matrix reads back with its frame length and no tempo.

## 3. P4.6 — `matrix/isochrony.py` is deleted

The plan left this open between deleting it and keeping it as an optional "tidy this run" action.
**Deleted**, and the reason is in its own module docstring.

It existed to fix one failure, described there from a real case: 25 right-hand attacks played evenly
at about 106.9 ms each, on a grid where a semicorchea was 84.27 ms. Each note was 1.27 columns, there
is no such figure, and an onset can only land on a whole column, so a perfectly even run printed as
seventeen semicorcheas and seven corcheas. The module's answer was to quantise the *sequence* rather
than each note: find a stretch that fits a constant spacing and place every onset in it at one
spacing.

That failure cannot occur any more. A column is 40 ms of wall clock and carries no figure, so a
106.9 ms gap is simply 106.9 ms; the figure comes from the ladder, which compares proportionally and
gives every note in that run the same name. The beat frequency between 106.9 and 84.27 has nothing
left to beat against.

Keeping it as an optional action was rejected on the same grounds it was written for. Evening out a
run means **moving onsets**, which contradicts D-03: the recorded times are the source of truth and
the page is where the notes were played. The one output of it that carried real information — "these
runs disagree with your tempo, try 139 BPM" — is what the peak plot now does, better and without a
tempo to disagree with.

`matrix/isochrony.py` and `tests/test_matrix_isochrony.py` are deleted. Nothing imported it after
P4.2 removed `derive`.

## 4. P4.7 — the text format carries `frameMs`

`sequence_to_score` produced a payload with `tempoBpm` and `timeStepSeconds`. Those two say the same
thing twice and can disagree, and one of them is a tempo, which D-01 removes. The payload now carries
`frameMs` and nothing else about timing (D-30).

The written notation itself is unchanged: one list item is one frame, `||` separates simultaneous
notes, `*` marks an onset. What changed is what a frame *is*. It used to be a note figure whose
length came from a tempo, so the same text meant different music depending on a number stored beside
it. It is now a fixed slice of wall clock, 40 ms by default, and what the notes are called is decided
later from a ladder the reader names.

`data/example-scores.json` was converted in place: each score's `timeStepSeconds` became its
`frameMs` in milliseconds, so the seed still describes exactly the same music.

Files: `matrix/text_notation.py`, `schemas/score.py`, `api/scores.py`, `data/example-scores.json`,
and the frontend types in `music/types.ts` and `api/scores.ts`.

## 6. Things I believed that turned out false

I believed `v2` on its own was the tidier scheme, because the frame length is not a property of the
music. It is not tidier, it is lossy: the repository already models "same state, second view" and
uses the folder name to hold it, so removing the suffix would have made two legitimate saves collide
and forced the distinction somewhere less visible.

I expected P4.7 to be a rename. It changed the meaning of the format rather than its spelling: the
same sequence of text now describes a fixed number of milliseconds per item instead of a number of
beats, so any text written under the old rules describes different music when read under the new ones.
Nothing on disk was affected because the only stored file, `example-scores.json`, was converted with
its numbers rather than its labels.

I also expected `matrix/isochrony.py` to be a hard call. It was not, once its own docstring was read:
the module names the exact failure it exists for, and that failure is arithmetic that a wall-clock
grid cannot produce.
