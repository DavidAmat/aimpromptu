# P2.6 — the split-peak regression

Task: P2.6 `[AITU]`. Decisions implemented: D-07.
Date: 2026-08-06. Status: done. **This test must never be deleted, weakened or skipped.**

## 1. Why it exists

D-07 says all peak finding runs on raw timestamps and never on snapped columns. That is not a
preference. If someone measures on columns, the code still runs, the plot still looks like a plot,
and every peak in it is split in two. The user is then asked to name a peak that does not exist in
the playing.

The failure is silent, which is why it needs a test rather than a comment.

## 3. What the regression does

It builds a shuffle: four hundred notes alternating a 211 ms long half and a 125 ms short half of a
337 ms beat, with six milliseconds of human jitter. That is the shape the measurement found on the
real recording.

Measured on raw times it finds **two** peaks, at 125 and 211 ms.

Measured after snapping the onsets to 40 ms columns it finds **more**, and the test names four of
them: near 120, 160, 200 and 240 ms. Each real peak has become a pair, because a gap lands on one
column count or the next depending on where in the piece the two notes fall.

The jitter is deliberate and the random seed is fixed, so the test is reproducible without being a
single hard-coded value that could pass by accident.

## 4. The guard

`peaks_of` refuses gaps that are all exact multiples of the frame length, so the regression has to
build its snapped density directly from `gaussian_kde` and `find_peaks`. That is the only place in
the codebase that should ever do it, and the comment there says so.

## 5. The exit criterion, now a test

The plan's exit for Phase 2 is that the peak table for *Mr Blue Sky* segment A reproduces the PoC's
125 / 211 / 337 / 463 / 674 / 799 within a millisecond. Two tests read
`poc-onset-duration-distribution/data/` and assert exactly that, including the masses
(29, 87, 265, 41, 42, 23), the dominant peak's median of 337.2 ms and its 50.2 % share. They skip
themselves when that folder is absent, so a checkout without the PoC data still passes.

## 6. Things I believed that turned out false

I expected the snapped measurement to produce exactly twice as many peaks. It produces more than
twice, because the merging rule that treats two maxima closer than 25 ms as one peak behaves
differently on a comb of 40 ms spikes. The assertion is therefore "more peaks than the raw run, and
these four specific centres exist", which is the claim D-07 actually makes.
