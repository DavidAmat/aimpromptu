# P2.1 — `matrix/intervals.py`, gaps between attacks

Task: P2.1 `[AITU]`. Decisions implemented: D-03, D-07.
Date: 2026-08-06. Status: done.

## 1. Why this module is separate from the matrix

Everything the user will be asked to look at starts here. The plot of gaps, the peaks and the ladder
all read the same numbers, so those numbers are produced in one place and the rule that protects
them is enforced in one place.

The rule is that gaps are measured on the raw float timestamps and never on columns. Rounding an
onset to a column before measuring splits every peak in two, because a 337 ms gap becomes 8 or 9
columns of 40 ms depending on where the pair happens to fall.

Gaps are also measured per hand. A right-hand run over a held left-hand chord produces gaps between
the hands that no player would call a rhythm, and mixing them fills the low end of the plot with
noise.

## 3. Decisions taken inside the task

**The D-07 guard is a real check, not a comment.** `check_measured_on_raw_times` refuses a set of
gaps where every value is an exact multiple of the frame length. A person cannot place forty
consecutive notes on 40 ms boundaries, so that pattern can only come from snapped data. Fewer than
eight values pass, because three round numbers can happen by chance.

**The range is applied to the attacks, not to the gaps.** A passage's first gap runs from its own
first attack to its second. Applying the range to gaps instead would let a passage inherit a gap
reaching back into the previous one, which would then be attributed to the wrong ladder.

**`IntervalSet` carries the count and the range, not only the numbers.** A passage with four gaps
and a passage with four hundred deserve different confidence, and the UI has to be able to say so.

## 4. Things I believed that turned out false

I expected to filter events by hand inside this module. It cannot: a raw event has no hand until the
split has run, and D-31 puts the split after the matrix is built. The module therefore takes
whatever events it is given and the caller passes one hand's worth. That is also what makes the
endpoint in P2.4 need a decision about where the hand label comes from.
