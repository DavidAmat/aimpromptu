# P4.2 — the pipeline stops making grids, and the old screens go with it

Task: P4.2 `[AITU]`, absorbing P1.5 and P1.6. Decisions implemented: D-01, D-03, D-30, D-31.
Date: 2026-08-07. Status: done, checked on screen. Raises and resolves issue I-06.

## 1. What the app does differently

There are two Playground tabs now, **Upload / Input** and **Rhythm**, and they are the whole path:
load a recording, transcribe it, name the gap you recognise, read the sheet.

The five tabs that were there before — Matrix, Piano Roll, Notes Falling, Notes Falling (raw) and
Music Notation — are gone. Section 2 explains why they could not stay, and section 7 says what was
lost with them.

Running a transcription now takes you to **Rhythm** when it finishes, instead of to the Matrix tab
that no longer exists.

## 2. Why the five tabs had to go, and the decision that was taken

The task as planned was to rewire `transcription/pipeline.py` onto the wall-clock path and delete
three modules: `matrix/granularity.py`, `matrix/approximation.py` and `matrix/tempo_map.py`.

Reading the code showed that those three modules were not only used by the pipeline. All five of the
older tabs read them, through `/matrix` and `/notation` routes that still asked for a tempo and a
granularity on every request. Deleting the modules would have left five tabs in the app that opened
and then failed.

The plan puts tab removal in P7.11 and marks it blocked on P4.5, so on paper P4.2 could not land at
all. The reason P7.11 was blocked was that the older tabs were the only way to open a stored
artifact until the migration had run. P4.1 measured that assumption and it does not hold here: there
is one stored artifact, its recorded notes are intact, and the Rhythm tab already reads it directly
with no migration step.

This was raised with the supervisor rather than decided here, because removing five screens is a
product choice and not a refactoring detail. **The instruction was to retire the five tabs now, in
this task.** It is recorded as I-06 in [`issues.md`](issues.md).

## 3. What the pipeline is now

The old pipeline had five steps, and the middle three existed to move a recording onto a grid whose
spacing came from a tempo. With no tempo, those steps have nothing to do:

```text
audio -> the engine's note events, in seconds   (events.json, kept forever)
      -> impose the frame length, split the hands
```

Only the first arrow is expensive, and **only its result is stored**. Everything after it is a
function of `events.json` and a frame length, so it is computed again on each request. That is what
makes `frameMs` a query parameter rather than a migration: asking for the same piece at 20 ms is
another request, not another artifact, and there is no file on disk that can disagree with the
screen.

Before this task a transcription wrote seven files into `data/audio/<uuid>/matrices/`. It now writes
one, `events.json`, and `tests/test_transcription_raw_events.py` asserts exactly that.

## 5. Decisions taken inside the task

**The backend stores nothing but the recorded notes.** The alternative was to keep writing the two
hand matrices so a screen could read them back. It was refused for the reason in section 3: a stored
matrix at 40 ms and a request for 20 ms are two answers to one question, and the file would win by
being there. Re-deriving a five-minute piece costs a second or two.

**The whole 1.x notation stack went, not just the tab.** `notation/durations.py` needed three table
functions from `approximation.py`, and it existed only to feed `score_builder.py`, which fed the
Notation tab and the pre-generated score written when a library version is saved. The Library screen
is an unbuilt placeholder and P4.1 found no saved versions on disk, so keeping that chain alive would
have meant moving code between modules to preserve something nothing calls. Saving a library version
no longer writes a `score.json`.

**Text notation and Matrix JSON were removed from the Upload / Input tab.** Both produced a matrix
with no recording behind it. Under the wall-clock model a page is drawn from the recorded onsets, so
neither had anything the sheet could be written from: they would have been buttons that lead
nowhere. The text-notation parser itself (`matrix/text_notation.py`) is untouched and is P4.7's
subject.

**`/matrix/{uuid}/events` stayed, minus two fields.** It is the only route upstream of the grid and
the thing everything else should be compared against when an answer looks wrong. It lost
`rawGranularity` and `matchesGrid`, which described a stored grid that no longer exists.

**The hand split reports a progress stage again.** The old `derive` wrapped it in a `two-hands`
stage and `time_pipeline` did not, so the progress bar would have skipped it. One `with` block.

**`matrix/isochrony.py` was left in place, unused.** Its only caller was the old `derive`. Deleting
it is P4.6's decision and it says so explicitly, so this task did not take it.

## 6. Things I believed that turned out false

I believed P4.2 was a backend task. It is not: the three modules it deletes are load-bearing for
five screens, and there is no order in which the backend half lands alone without leaving the app
broken. Any future task in this plan that says "delete module X" is worth checking against the
frontend before it is scheduled.

I believed the deletions would be contained, because the plan named three modules. They pulled in
the whole 1.x notation stack, nine more backend files and about thirty frontend ones. The reason is
that `approximation.py` was Appendix C, the rule about which durations may be written at all, and
every screen that printed a note asked it.

**`vexflow-v2/dist/` on the development machine is stale, and this is not caused by P4.2.** The
frontend imports the built package rather than its source, and the build on disk is dated 2026-08-02
while the source has changed on the 6th and the 7th. So the local app has been drawing with a
renderer that predates beams (P6.7), tuplet brackets (P6.10) and beam breaks (P6.12). Earlier tasks
checked those features on screen in their own container, where they had built the package, and never
wrote the result back. The rebuilt `dist/` ships with this task, and section 9 says what to look for.

## 7. What was lost with the five tabs, stated plainly

The Matrix tab's grid editor, the piano-roll view, the two falling-notes views and the 1.x engraved
score are gone, and nothing replaces them yet. Concretely, there is no longer a way to look at a
transcription as a piano roll, to edit a cell by hand, or to export and re-import a matrix as JSON.

Two of those were genuinely useful for auditing a transcription, and the Rhythm tab does not do their
job. If any of them should come back on the wall-clock path, that is a new task and worth deciding
before Phase 8 rather than after.

## 8. Tests

The whole backend suite passes: **583 tests, 5 skipped, no failures.** Both pre-existing failures are
gone. `test_api_smoke.py::test_scores_returns_a_list` passes, and
`test_transcription.py::test_changing_the_bpm_reinterprets_the_same_grid` was **deleted** with the
rest of the 1.x pipeline section, which is what P4.8 asks for. P4.8 therefore inherits a green suite
rather than a repair job.

Rewritten rather than deleted, because the behaviour still matters:

- `test_transcription_leakage.py` and `test_transcription_artifacts.py` now build through
  `events_to_time_matrix`. The Bruno Mars phantom re-onset is still merged, and the phantom octave
  still never reaches the grid.
- One artifact test changed its meaning and says so. Asking for the engine's events verbatim
  (`artifacts=None`) used to place the 5.7 ms phantom Fa-1 on the grid. It no longer does, because a
  note shorter than one frame is refused by D-05 whatever the artifact filter thinks. Two rules agree
  here by coincidence rather than by construction, and the test now pins that.
- `test_transcription.py`'s placement section was removed rather than ported: the wall-clock builder
  is tested directly in `test_time_matrix_build.py`, and two copies of the same assertions drift.
- `test_hands_persistence.py` keeps only its schema section. The stored hand map it guarded does not
  exist for a working artifact any more.

Lint and types are clean. `flake8` reports nothing. `mypy` reports six errors, all present on the
baseline before this task and none in a file it touched; two baseline errors disappeared with the
rewrite. `black` leaves four files unformatted and all four were unformatted before this task.

`npm run lint` and `tsc -b` are clean in `aitu-frontend`.

## 9. Checked on screen

Both services were started in a container against the real *Mr Blue Sky* recording and driven with a
browser.

- The Playground has two tabs, **Upload / Input** and **Rhythm**.
- Upload / Input lists the audio, shows the waveform and the segment tools, and offers one timing
  choice, "Time resolution", with no BPM anywhere.
- Rhythm draws the peak plot from the rewired backend: 755 gaps between 756 right-hand notes, piles
  at 67, 120, 219, **337**, 463, 674, 750 and 799 ms. Those are the values the proof of concept
  measured, so the measurement survived the rewiring intact.
- Naming the 337 ms pile a negra writes the sheet: a grand staff with beamed runs, tresillo
  brackets, no bar lines and no rests.
- No console errors on either tab.

**What to check yourself.** Open `http://localhost:5173`, go to **Playground**. There should be two
tabs. On **Upload / Input** pick *MR BLUE* from the audio library, then open **Rhythm**: the plot
appears, the 337 ms bar is already selected, and pressing **Write the sheet** draws the staff.

Please also confirm the renderer is current, because your local build of it was five days old until
this change: on the sheet, runs of short notes should be **joined by beams** rather than each note
carrying its own flag, and groups of three should carry a **bracket with a 3** over them. If either
is missing, the package did not rebuild and that is worth telling me.
