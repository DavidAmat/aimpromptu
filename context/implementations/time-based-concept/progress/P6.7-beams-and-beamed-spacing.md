# P6.1 and P6.7 — beams, and the space inside a beamed run

Tasks: P6.1 `[GN]` completed, P6.7 `[GN]` answered. Decisions implemented: D-11, D-12, D-26.
Date: 2026-08-07. Status: done, checked on screen.

## 1. What was wrong

Runs of corcheas printed as separate notes, each with its own flag. An evenly played run is one
gesture and a row of flags does not read as one, however even the timings underneath are.

Two causes, and the second is the interesting one.

The first is that the score view asked the renderer not to beam. That was mine, and it was a
one-line mistake.

The second would have made beaming wrong even with the flag on. The beam planner and the spacing
measurer both worked out each note's figure from **how many columns it covers**. Under a wall-clock
grid that number says nothing about what a note is called: the backend names the figures from the
playing and sends them. So notes would have been beamed by a figure the page never shows, and
measured for a glyph it never draws.

## 3. Decisions taken inside the task

**`PrintedFigureLookup` moved to `figure-selection.ts`, with a `namedFigure` helper.** Three
modules now have to answer the same question, and each one deriving it separately is how they would
drift.

**P6.7 is answered: a beam groups a maximal run of consecutive beamable notes in one hand**, split
where the melody turns, where the key or clef changes, and where a cue passage starts. It is not
grouped by beat, because there is no beat. That is the package's existing rule; what changed is that
it now reads the printed figure, so the runs it finds are the ones the page shows.

**A beamed note keeps 35 % of the usual space after it, and the empty columns inside a run shrink
by the same fraction.** The beam already carries the eye across the group, so the whitespace between
the noteheads is doing no work and full width makes the run read as loose notes. Measured on screen,
the clear space between two beamed corcheas is now about half the space between two negras, which is
what the supervisor asked for.

**Only a completely empty column is closed up.** The first attempt shrank every column between two
beamed onsets and printed the left hand's notes on top of each other, because a column carrying the
other hand had already asked for its width. A column is only tightened when nothing at all has
claimed it, and only between two beamed onsets of the same hand.

## 4. Things I believed that turned out false

I believed turning beaming on was the whole fix. It was about a fifth of it. Beaming reads the
figure, and every module that reads a figure had to be told to ask the host first, or the beams
would have grouped by the grid.

I also believed the tighter spacing could be a single constant on the note. It cannot: most of the
distance between two onsets is the empty columns between them, so leaving those at full width left
the run almost as wide as before.

## 5. Tests

`tests/beamed-spacing.test.ts`, four tests: a run the grid would not have beamed is beamed once the
host names it; a beamed run sits at roughly half the clear space of the same notes unbeamed; the
space into and out of a run is unchanged, so a run stays distinct from its neighbours; and nothing
is ever taken from a column the other hand is using.

The package's suite is otherwise unchanged. Checked on screen with a piece alternating runs of four
corcheas with pairs of negras.

## 6. What is left

Beam slant and stem length are the package's existing rules and were not touched. If a steeply
ascending run looks wrong, that is the next thing to look at.
