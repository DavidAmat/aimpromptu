# P2.2 — `matrix/peaks.py`, finding the piles

Task: P2.2 `[AITU]`. Decisions implemented: D-07, D-08.
Date: 2026-08-06. Status: done.

## 1. What this produces

The app does not choose the rhythm. It shows where the gaps pile up and how much of the playing each
pile holds, and the user names one of them. Interval statistics cannot settle the question alone: a
beat and twice that beat explain the same gaps equally well, and on the second half of the piece
that was measured, two candidates scored within 0.1 % of each other.

## 2. Files

Added:

- `aitu-backend/src/aitu_backend/matrix/peaks.py`

Ported from `poc-onset-duration-distribution/scripts/analysis.py`, with the defaults that produced
the table in `RESULTS.md`: a 12 ms smoothing bandwidth, a density evaluated every millisecond up to
1200 ms, a peak kept when its basin holds at least 2 % of the gaps, and two maxima closer than 25 ms
treated as one.

## 3. Decisions taken inside the task

**The guard runs first, inside `peaks_of`.** Measuring on columns is silent when it happens and
produces a plausible plot with every peak split, so the refusal has to be in the path everyone uses,
not in a helper that a caller can skip.

**The bandwidth is fixed in milliseconds.** What is being smoothed over is human timing jitter,
which is roughly constant in absolute terms. A bandwidth that adapted to the spread of the data
would widen with the long-rest tail and erase the fast peaks.

**A basin is a partition.** A peak's mass is the gaps between the neighbouring density minima, so
every gap belongs to exactly one peak and the shares of two different passages can be compared.

**`gaussian_kde`, `density_grid` and `find_peaks` are exported separately** from `peaks_of`. The
regression test in P2.6 has to build a density from snapped data on purpose, and `peaks_of` refuses
that by design.

## 4. Things I believed that turned out false

I expected the port to need tuning to reproduce the measurement. It reproduces it exactly: the same
six peaks, the same masses, the same shares, to the millisecond. The parameters in the PoC were
already the answer.

## 5. Tests

right hand of segment A comes out as 125, 212, 337, 463, 674 and 799 ms with masses 29, 87, 265, 41,
42 and 23, which is Phase 2's exit criterion and is now guarded by a test rather than a note.
