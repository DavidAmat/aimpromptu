# 1. P5.5 — a frame stops having a beat value

Task: P5.5. Contract: §1, the row that reads `BEATS_PER_FRAME[granularity]` becomes *(gone)*.

## 1.1 Why this was needed

A 1.x file said what one column was worth with a `granularity` code: `semicorchea` meant a column was
a sixteenth, so a column was a quarter of a beat. The package turned that code into a number,
`BEATS_PER_FRAME[granularity]`, and everything that needed a duration multiplied by it. A note
covering six columns was a beat and a half, and a beat and a half is a dotted negra, so the figure
followed from the grid.

A column is now 40 ms of wall clock and says nothing about music. Six columns is 240 ms, and whether
240 ms is a corchea or a negra depends on the ladder the user named, which the package does not have
and must not guess. Keeping the table means keeping a rule that produces a confident wrong answer.

## 1.2 What was built

`BEATS_PER_FRAME` is deleted. Where a duration in beats is still needed, the package asks the host
how many frames one negra covers, through a new option called `framesPerQuarter`. This is the same
number the old table produced, written the way the time-based model states it: the grid does not
know, the person reading the music does.

- `src/matrix/types.ts`: the table is gone. `DEFAULT_FRAMES_PER_QUARTER` (4) takes its place, which
  is what `semicorchea` used to mean, so a host that says nothing draws exactly what it drew before.
  `Granularity` survives as a label on a stored 1.x file and is deleted with the rest in P6.9.
- `src/matrix/events.ts`: `extractMatrixMusic(envelope, { framesPerQuarter })`. The returned
  `beatsPerFrame` field is now `framesPerQuarter`. The warning that compared `timeStepSeconds`
  against the header's tempo and granularity is deleted, because the three no longer describe the
  same quantity and cannot disagree.
- `src/renderer/grid-notation-renderer.ts`, `draw-grand-staff.ts`, `notation/beam-groups.ts`,
  `notation/draw-music.ts`, `notation/spacing.ts`, `ruler/frame-ruler.ts`, `edit/merge-onsets.ts`,
  `print/render-pages.ts`, `editor/grid-notation-editor.ts`, `perf/song-fixture.ts`: the option and
  the arithmetic follow. A duration in beats is `frames / framesPerQuarter` instead of
  `frames * beatsPerFrame`.
- `notation/spacing.ts`: `defaultPixelsPerFrame` and `pixelsPerFrameForMusic` take
  `framesPerQuarter` instead of a granularity code.
- `matrix/load-envelope.ts`: the 1.x header reader stopped completing a missing field from the other
  two. A file with no `timeStepSeconds` gets the default frame of 40 ms with a receipt in the
  warnings; a file that has one keeps it untouched.
- `docs/api.md` and `docs/integration.md`, for the renamed option.

A wall-clock score never reaches any of this. It names every figure through `printedFigureFor`, and
the Rhythm screen already does.

## 1.3 Decisions taken inside the task

The number is expressed as frames per negra rather than beats per frame. Both say the same thing,
but a host has to supply it now, and "how many columns is a negra" is a question a person can answer
from the ladder they just named. "How many beats is a column" is not.

`DEFAULT_FRAMES_PER_QUARTER` is 4 rather than being required. Making it required would have broken
every demo artifact and about forty test files at once, for a value only a score that names no
figures ever reads. The default is documented as what the old `semicorchea` code meant, so no drawing
changed.

## 1.4 Things I believed that turned out false

I believed the renderer took its beat value from its own options. It did not. It read the envelope's
granularity through `extractMatrixMusic` and used its own `beatsPerFrame` option only for the ruler's
guide spacing, so the two could describe different music. Epic 3, whose passage is labelled `fusa`
(eight frames to the negra), was the case that showed it: the renderer kept drawing at the default of
four until the option was passed through to `extractMatrixMusic`. The renderer now reads its music
through one place, `readMusic`, and that place passes the host's answer on.

## 1.5 Tests

Two checks asserted the deleted arithmetic and were rewritten rather than removed, because both still
have something to pin:

- `tests/matrix-events.test.ts` asserted that a `timeStepSeconds` disagreeing with the header's tempo
  produced a warning. It now asserts that how many frames a negra covers comes from the host, that it
  defaults to 4, and that a value of zero is refused.
- `tests/load-envelope.test.ts` asserted that a missing frame length was derived from tempo and
  granularity. It now asserts that a missing one falls to the 40 ms default with a receipt, and that
  a supplied one is kept and no longer reported as a disagreement.

`tests/engraving.test.ts`, `beam-groups.test.ts`, `bars.test.ts`, `clef-changes.test.ts`,
`cue-notes.test.ts`, `key-changes.test.ts`, `stems-and-merge.test.ts` and `frame-ruler.test.ts`
changed the name and the reciprocal of the value only.

Whole package: 43 files, 395 checks, none failing. `tsc -b`, `eslint`, `prettier` and
`npm run build` are clean, and all eight artifacts rebuild.

Looked at in a browser: `deliverables/epic-01-rendering-core.html`, `epic-03-notes-on-grid.html` and
`epic-04-beams-and-grouping.html` all draw with no console errors, and Epic 3 reports the same
twelve onset groups, twenty notes and three rests it did before.

## 1.6 Left open

`src/notation/metre.ts` still computes beats per frame from its own bar plan. That module is deleted
in P6.3.
