# 1. P6.8 — version 0.28.0, and the documentation catches up

Task: P6.8. Contract: §1.

## 1.1 Why this was needed

Five tasks in a row deleted things, and the package's documentation still described them. A reader
following `docs/integration.md` would have implemented a tempo callback that no longer exists,
supplied a per-frame timestamp array the clock no longer accepts, and expected an envelope header
with a tempo and a granularity code in it. Documentation that describes a version ago is worse than
none, because it is followed.

The **BPM** tab had the same problem in the product itself. It let a reader select a stretch, name a
tempo for it, and hand that intent to the host through `onTempoRequest`; the host then re-quantised
the stretch, which changed how many columns it occupied, and returned a new envelope. That whole
exchange assumed a column was a note figure. Nothing about the recording changes now when a reader
decides the piece is faster than they thought: what they are naming is which printed figure a gap
carries, which is the ladder, and the ladder lives on the Rhythm screen.

## 1.2 What was built

The version is **0.28.0**.

Deleted: the `onTempoRequest` callback, the `TempoRequest` type, the editor's **BPM** tab and its
panel, the tempo input and its Apply and Restore buttons, and the editor's own `framesPerQuarter`
option, which existed only so that panel could print a BPM. The renderer keeps its
`framesPerQuarter`, where it is a real input.

Rewritten, with what each replaced said and why it is wrong now:

- `docs/integration.md` §2, which listed `tempoBpm`, `timeStepSeconds` and `granularity` as part of
  what AImpromptu sends; §4, which described switching granularity; and the whole `onTempoRequest`
  section, which is now a short statement that there is no tempo and nothing to ask a host for.
- `docs/api.md` §Time, §Bars, §Loading a matrix file, the renderer option table, and the DOM contract
  rows for the deleted Bars controls.
- `docs/contracts.md`, which said `timeStepSeconds` was authoritative and that a tempo and
  granularity disagreement produced a warning.
- `README.md` §Scope, which said bar lines could be drawn as an overlay, and the nuance list.

Every remaining use of the word "barline" for a key or clef change is now "vertical line", because a
barline is a measure boundary and these are not.

## 1.3 Decisions taken inside the task

The deleted sections were replaced with a paragraph saying what used to be there and why it went,
rather than being removed silently. A reader who knows 0.27.0 needs to be told that the callback is
gone and what to do instead; a blank space reads as an accident.

## 1.4 Things I believed that turned out false

I believed the editor's `framesPerQuarter` and the renderer's were the same option arriving twice.
They are not. The renderer's decides how figures and beams are chosen when the host names none; the
editor's only supplied a number for the BPM tab to print. Removing the tab therefore removes the
editor's copy and leaves the renderer's, which is the opposite of what deleting a duplicate would do.

## 1.5 Tests

No check was removed, because no check covered the BPM tab. `tests/hand-scope.test.ts` names the
toolbox tabs and did not include it. That gap is worth recording: a panel with an input, two buttons
and a callback shipped in 0.27.0 with no test, which is why nothing failed when it was deleted.

Whole package: 42 files, 365 checks, none failing. `tsc -b`, `eslint`, `prettier`, `npm run build`
and `npm run build:deliverables` are clean.

Looked at in a browser: `deliverables/editor.html` opens with the toolbox tab row missing **BPM** and
reports no console errors.

## 1.6 Left open

`docs/epic-0-vexflow.md` still names bar lines and time signatures. That file records what was taken
from VexFlow and what was discarded in Epic 0, so it is a historical record and is correct as it
stands.
