# Pregunta 4: Si Sonnet cambia la mano de una nota, ¿qué pasa con las manos que ya corregiste tú?

A ver, aquí está el tema: el LLM va a ser el primero que decida las manos, como ya te he explicado en la pregunta anterior. No hay ningún escenario en el cual el usuario pueda cambiar una nota porque solamente dejaremos editar los pasajes en los cuales el LLM ya lo haya decidido.

En el caso de que haya un fallo y el LLM no pueda decir nada, vamos a dejar que el usuario haga estos cambios manualmente. Por detrás lo que tú tienes que hacer es conseguir que el backend, una vez el usuario cambie algo de una asignación de una nota en una mano o en otra, cambie el formato de la matriz. Una vez el LLM haga cambios en qué notas se tocan en cada mano, eso se debe transformar por detrás en dos matrices de nuestra nueva notación: una para la mano izquierda, otra para la mano derecha, con los cambios de las notas que se han pasado de una mano a otra. Entonces cuando el usuario cambia esto, simplemente está modificando la matriz subyacente. Cuando el usuario lo modifica, si queremos que el LM vuelva a predecir el formato o a mejorar el formato, una vez haya hecho los cambios, la notación acción subyacente va a enviar al LM esa información ya con los cambios modificados del usuario (ya que la matriz de esa partitura, la matriz subyacente, ya tiene los cambios que ha introducido el usuario). De esta forma la idea es que siempre haya una representación numérica de las decisiones que se toman en el tema de las asignaciones de las notas por mano, De forma que cuando se tenga que introducir de nuevo el LLM, simplemente haya que transformar una representación numérica a una representación textual para que el LLM lo pueda ingerir y entender.
