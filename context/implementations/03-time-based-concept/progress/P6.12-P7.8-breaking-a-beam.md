# P6.12 and P7.8 — breaking a beam

Tasks: P6.12 `[GN]` and P7.8 `[AITU]`, both added during the task. Decisions implemented: D-34 (new).
Date: 2026-08-07. Status: done, checked on screen.

## 1. Two questions that look like one

David asked two things about beams, and they turn out to be different in kind.

**Does renaming one note re-form the beam?** A corchea inside a beamed run, renamed to a negra,
cannot stay under the beam — the run has to become two. This one already worked, and it works for a
reason worth stating: beaming reads the **printed** figure, not the grid. P6.7 made every module that
asks what a note is called ask the host first, and the per-note override goes into the same lookup
the beam planner reads. So the grouping followed the rename with no code at all. `beam-breaks.test.ts`
now pins it, because it worked by construction and could have stopped working the same way.

**Can a reader break a beam by hand?** This one needed building. A long run climbing through an
arpeggio has no boundary inside it that any rule can find — one hand, one key, one clef, no tuplet —
so it beams as a single shapeless slope with stems reaching across two octaves. A player hears two
gestures. Where the second one starts is a reading of the music rather than a property of it, and no
amount of cleverness in the planner will produce it.

## 2. What the package already did

The package cuts a run at a **returning low note**: a local minimum inside a window is treated as the
start of the next figure. That is precisely the arpeggio case David described — "whenever we go back
to the lowest note we want to start a new group" — and it needed no work.

This was worth finding out before building anything, and it changed the demo. A line that returns to
its bottom note is split automatically, so it demonstrates nothing about the new feature. The demo's
run climbs, turns once at the top, and descends: no interior low point, nothing for any rule to catch,
one beam of sixteen. The break a reader wants there is at the turn, and only a reader can say so.

## 3. What was built

`beamBreakAt(hand, onsetFrame) => boolean` in the renderer, and **Break the beam here** on the
selected note in the Rhythm screen, beside the figure picker. Pressing it again joins the beam back.

Three properties, each deliberate:

**Applied last.** After the figure split, the key and clef splits, the cue split, the tuplet split and
the arpeggio low-point split. A person's answer beats the rules rather than competing with them.

**Keyed by the note's own column.** Not by its position in the run, which changes the moment anything
else about the grouping changes, and not by a run length, which would go stale on a rename. A column
never moves, so a break survives a ladder change untouched — which matters, because the reason to
break a beam and the reason to rename a figure are unrelated and a reader will do both.

**Stranding is not an error.** A break on the second note of a run leaves the first with nobody to
beam to. It takes a flag, which is what a lone corchea is, and the rest of the run is unaffected.

## 5. Things I believed that turned out false

I believed the arpeggio case needed building. It was already there, and building the demo around it
would have produced a screenshot of the old rule working and called it the new feature.

I believed the demo's two runs — one in corcheas, one in semicorcheas — would beam separately by
being different figures. They do not, and should not: a beam happily mixes figures and gains a level
for the shorter ones, which is the whole point of the mixed run in the right hand. The two are
separated by a negra between them, because a beam stops at the first note that cannot be under one.

## 6. Tests

`tests/beam-breaks.test.ts`, six tests: a rename to an unbeamable figure splits the run; a reader's
break starts a new group and changes no figure; the same on a run of semicorcheas, with the second
beam level intact; several breaks in one run; a break that would strand the first note leaves it a
flag; and no breaks changes nothing.

`test_time_score_payload.py`, two more: a break carries a hand and a column and nothing else, and a
score with no breaks says so with an empty list.

## 7. Checked on screen

The demo piece gained two long left-hand runs after the tresillos — sixteen corcheas and sixteen
semicorcheas, both climbing two octaves and coming back — with the right hand holding above them.

Before: the corchea run is one beam of sixteen, drawn flat and far above the staff because the group
spans two octaves, with the stem of every note reaching up to it. Unreadable, and exactly the
complaint.

After breaking on the ninth note: two beams, one rising into the turn and one falling out of it,
each following the notes it covers. The same break on the semicorchea run does the same thing with
both beam levels intact. No console errors, and no note moved in time.

## 8. What is left

Breaks are held in the screen's state alongside the figure overrides, and go when the tab does. The
payload has the `beamBreaks` field for them, so when a named rhythm is saved with the piece both
travel together — that is still the same unbuilt piece of work.
