# 1. P6.4 and P6.5 — the ruler reads the layout hints, and a passage says what it is

Tasks: P6.4 and P6.5. Decisions: D-27, D-20.

Written as one report because both are the same missing wire. The payload has carried `frameGroup`,
`frameMeasure` and each passage's `headerLabel` since Phase 3, and the drawing package had no option
to receive any of them.

## 1.1 Why this was needed

**The ruler.** A dashed line and a selectable region were the same thing. The package chose one
spacing from the average column width and used it for both, which is a sensible default and answers
the wrong question twice: a line a reader looks past wants to be sparse, and a region a reader drags
across to mark a speed change wants to be small enough to name a phrase with. On the real recording
the one spacing came out at sixteen columns, so the page carried a line every 0.64 seconds, which is
close enough to a grid to read as one, and a passage could only be drawn in 0.64-second steps.

D-27 separates them: `frameMeasure` is where a line goes, `frameGroup` is what can be selected, and
neither has a musical meaning. The backend already sends 100 columns (four seconds) and 25 columns
(one second).

**The header.** A conventional score prints a tempo mark, and this one cannot: there is no tempo. It
prints what the reader decided instead, `negra = 337 ms · ≈178 BPM`, which is the same information
in the unit the ladder is actually in, with the tempo restated for a reader who thinks in BPM
(D-20). Until now the Rhythm screen printed that line in the page's own chrome, above the sheet.
That is fine for a piece with one ladder and wrong the moment there are two, because a header belongs
where its passage starts and not at the top of the screen.

## 1.2 What was built

`src/ruler/frame-ruler.ts`: `frameGroup` and `frameMeasure` on `GuideDensityOptions`. The dashed
lines and their labels are built from `frameMeasure`, the selectable regions from `frameGroup`, and
each falls back to the chosen spacing when the host gives neither, so the editor is unchanged. The
ruler group carries `data-guide-step` and `data-group-step` so a test can read both. A value that is
not a positive count of frames is refused rather than rounded.

`src/notation/passage-headers.ts` is new: `drawPassageHeaders` takes `{ startFrame, label }` pairs
and draws each one at its own frame's x, above the treble staff, on the system that contains it. The
label is drawn verbatim; the package does not compose it, because the ladder is the backend's.

`src/renderer/grid-notation-renderer.ts` and `draw-grand-staff.ts` pass all three through.
`src/index.ts` exports the new module.

`aimpromptu/aitu-frontend/src/components/time/TimeScoreView.tsx` supplies them from the payload it
already receives: `score.layout.frameGroup`, `score.layout.frameMeasure`, and one header per entry in
`score.passages`.

## 1.3 Decisions taken inside the task

A header is drawn once, where its passage begins, and not repeated at the top of every line. A
printed score repeats a tempo mark because a reader opening the page in the middle has nothing else
to go on. Here the ruler above every system prints the wall clock, so the page already says where it
is, and a line repeated on every system would be noise.

The label keeps its frame number rather than becoming a timestamp. A reader can already click a
label to reveal the time, and changing what the ruler prints belongs to a task about the ruler's
labels rather than to this one.

## 1.4 Things I believed that turned out false

I believed a passage header would need room reserving above the staff, and that adding one would
push every system down. It does not: the ruler already reserves 52 pixels above the treble staff for
its label row and a revealed timestamp, unconditionally, precisely so that revealing one moves
nothing. The header fits inside that strip.

## 1.5 Tests

`tests/layout-hints.test.ts` is new, with five checks: that a piece with `frameGroup` 4 and
`frameMeasure` 16 draws five dashed lines and sixteen selectable regions over 64 columns, that the
first region is columns 0 to 4; that one spacing still does both jobs when the host names neither;
that a level which is not a count of frames is refused; that each passage header is drawn once, at
its own frame, in payload order, with the later one to the right of the earlier; and that a piece
with no passages draws no header group at all.

Whole package: 43 files, 370 checks, none failing. `tsc -b`, `eslint`, `prettier`,
`npm run build` and `npm run build:deliverables` are clean, and `tsc -b` and `eslint` are clean in
`aitu-frontend`.

Looked at in a browser, against the real recording. The Rhythm tab's staves now carry
`negra = 337 ms · ≈178 BPM` above the first system, and the ruler prints f0, f100, f200 and so on,
which is a line every four seconds instead of every 0.64. No console errors.

## 1.6 Left open

The Rhythm screen still prints the same ladder line in its own chrome above the sheet. Now that the
staff carries it, that copy is a duplicate, and removing it is a product choice rather than a
rendering one.
