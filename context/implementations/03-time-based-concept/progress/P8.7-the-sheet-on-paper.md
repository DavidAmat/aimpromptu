# 1. P8.7 — the sheet on paper

Task: **P8.7, new.** Not in `plan.md`. Asked for directly: *"a button in the rhythm page in which we
can download the piece as a pdf … only the part that we do the music rendering … you will need to
apply the kind of A4 paper dimensions … we can allow narrowing the margins so that the notes get
rendered in a new line, so the pdf should look perfect."*

## 1.1 Why this was needed

Nothing left the screen. The Rhythm tab drew a sheet as wide as the window happened to be, and a
piece read, keyed, fingered and bracketed over an hour could not be printed, sent to anyone, or put
on a music stand. It was also the one part of the product with no artefact at the end of it.

## 1.2 What was built

**`vexflow-v2` — `GridNotationRenderer.renderPages(container, options)`.** The package already had
`renderScorePages` and `planPages` (D41) but only the editor could reach them, and the app draws
with the renderer. The new method is the seam: it hands `renderScorePages` everything the screen was
using, and in particular **the frame widths this renderer already measured**.

That last part is the whole reason it is a method rather than a call site.
`renderScorePages` will measure its own widths, and it does not take `silenceGroupPx` or
`frameGroup` — the two numbers that decide how much room a silence is given — so measuring afresh
prints the same piece with different spacing from the one that was approved on screen. It also
turns off the editing chrome: frame cells, range corner marks, timestamps.

**`aitu-frontend/src/components/time/ScorePdfDialog.tsx`** — the panel behind the new **PDF** button
on the floating bar. Paper (A4 / Letter), orientation, side margins, top-and-bottom margins, a title
and a second line, page numbers, and a live preview of the actual pages. The preview is not a
picture of the PDF; it *is* the DOM the PDF is written from, so what is approved and what is
downloaded cannot drift apart.

**`aitu-frontend/src/print/`** — the PDF writer, four files and no new dependency:
`pdf.ts` (objects, streams, `FlateDecode` through `CompressionStream`, xref), `opentype.ts` (enough
of an OTF to embed it and find a glyph), `drawPage.ts` (one `.grid-page` element → drawing
operators) and `scorePdf.ts` (assembly, the embedded font, the download).

**`aitu-frontend/public/fonts/bravura.otf`** — the music font, fetched only when a PDF is asked for,
with its OFL licence beside it.

**`aitu-frontend/src/components/time/TimeScoreView.tsx`** — one new prop, `onRendererChange`, which
hands the live renderer up to the page.

## 1.3 Decisions taken inside the task

**Vector, not a photograph of the page.** The drawn page is already SVG — lines, rectangles, filled
polygons and glyphs, and nothing else — so every one of those is written as the PDF operator that
means the same thing. Rasterising twelve A4 pages at print resolution would have been megabytes of
image and soft at any zoom; the vector file is 450 kB, most of it the font.

**The margin is a control, not a constant.** This is the direct answer to what was asked for.
Because a page is a narrower available width and the music re-wraps to it (D5), the margin is
exactly the knob that decides how much music fits on a line: 14 mm → 12 pages, 5 mm → 11, 35 mm →
17, and nothing changes size at any of them.

**Per-glyph placement for the notation, per-word for the text.** A music glyph is written at the
position the engraver computed for it, so the PDF and the screen agree by construction and no font
metrics are reimplemented. Words are not: the labels are laid out in whatever sans face the machine
has and the PDF writes Helvetica, so placing each *letter* at the browser's position printed
Helvetica shapes with another font's letter spacing — visibly gappy, and the first version did
exactly that. Each word is placed once and left to space itself.

**Bravura travels with the file, the text faces do not.** The notes are at private-use code points
that mean nothing outside the font, so it is embedded whole as `Type0` / `Identity-H` /
`CIDFontType0` and addressed by glyph id. The labels use the PDF's built-in Helvetica, Times and
Symbol, which cost nothing — `Symbol` only because `≈`, in the passage header, has no WinAnsi slot.

## 1.4 Things believed that turned out false

**That the panel's host element could be read from a ref in the first effect.** MUI mounts a
dialog's contents a render *after* it opens, so the ref was still empty, the effect returned early
and never ran again — the panel opened and said "Nothing to print yet." It is held as state now, so
the node's arrival is itself what starts the drawing. This only surfaced after an unrelated tidy-up:
the earlier version seeded the title in an effect, which changed the options and re-ran the draw a
second time, by which point the ref happened to be full. It worked by accident.

**That `renderScorePages` was enough on its own.** It looked like the whole feature until the
spacing question came up. See 1.2.

## 1.5 Tests

No unit tests. Verified by running both repos in a Linux container against the real backend and the
cached transcription for `d3c6aa6e` — 2 639 notes, 4 min 52 s — and driving Chromium:

- The button opens the panel, the panel draws **12 A4 pages**, and clicking **Download PDF**
  produces a 450 kB file.
- `qpdf --check` reports no errors. `pdffonts` shows Bravura embedded as `CID Type 0C (OT)`.
  Rendered independently with poppler and parsed with pdf.js — twelve pages, 60 000 operators, and
  the title reads back as text.
- **Nothing off the margins.** Every one of the twelve pages rendered and measured: ink starts at
  14.3 mm from the left and stops no closer than 16.7 mm to the right, against a 14 mm margin.
- **Every line carries on where the one above it stopped.** The 36 systems tile the piece f0 → f7304
  with no gap and no overlap, across all twelve page turns.
- **The same page, screenshotted from the browser and rendered from the PDF, differs only at the
  edges of shapes** — antialiasing — and at the sans labels, where the letterforms are Helvetica's.
  Every notehead, stem, beam, clef, accidental, brace and octave bracket is registered exactly.
- The margin slider re-wraps rather than scales, in both orientations and on both paper sizes.

`npx tsc -b` clean. `npx eslint` reports only the pre-existing `controls.current` immutability error
in `ScorePlayer.tsx`. `npm run build` clean in both repos.

## 1.6 Cross-repo change

`vexflow-v2`, one file: `src/renderer/grid-notation-renderer.ts` gained `renderPages()`. Staying in
`aitu-frontend` was not enough because the options a printed page needs are the renderer's private
state — the frame widths it measured, `silenceGroupPx`, `frameGroup`, the annotations — and a call
site assembling them by hand is exactly what the package's own `printableOptions()` comment warns
against. No interface moved: `renderScorePages` is unchanged and the new method only calls it.
`docs/api.md` gained the paragraph. Committed there as *"A host that draws with the renderer can put
the score on paper"*; that file also carried another session's in-flight playback-cursor work, which
the commit preserves.

## 1.7 Left open

- The sans labels are Helvetica in the file and Inter on screen. Making them identical means
  shipping a text font as well; it did not seem worth 300 kB for the ruler numbers.
- No page-break control. A reader cannot say "start a new page here" — the package has
  `setForcedBreaks`, and the panel does not expose it.
- Gradients, clip paths and images are not translated. The drawing package emits none of them.
