# 1. P7.15 — a marked stretch shows its own corners, and its edits can be undone one at a time

Task: **P7.15, new.** Not in `plan.md`.

## 1.1 Why this was needed

A stretch that carries an edit was invisible unless it happened to be selected. A reader who gave a
passage its own key and came back an hour later had no way to find it again except by remembering
which columns they had used, and no way to undo one edit without undoing whatever else was on that
stretch.

## 1.2 What was built

Almost nothing, which is the point: the drawing package has had `collectRangeMarkers` and
`drawRangeMarkers` since before this refactor, and the Rhythm screen had never switched them on.
Two corners are drawn for every stretch carrying markup, one at the top of the system and one at the
bottom, each pair in its own colour from a nine-colour wheel so that two overlapping stretches are
told apart. The colour is per *range* rather than per kind, because the row a corner sits on already
says the kind and the one thing a row cannot answer is which range.

`TimeScoreView` now passes `rangeMarkers: true` and reports a corner click. `RhythmPage` selects
that stretch and opens the Frames toolbox on it.

The toolbox gained an **On this selection** list. Each row is one stored edit, named as it was made,
with its own **Remove**. A stretch can carry more than one thing, and undoing all of them because
you wanted one gone is not an undo. The list is derived from what is stored rather than kept in
state, because an edit list that can disagree with the edits is worse than no list.

Today the list holds key changes. Anything else that stores a stretch joins it by adding one entry
to the same derivation.
