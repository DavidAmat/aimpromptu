# 1. P7.12 — choosing the key the piece is written in

Task: **P7.12, new.** It is not in `plan.md`. Decisions: none; the key signature is not mentioned in
`decisions.md` or in the PRD.

## 1.1 Why this was needed, and why it was missing

A transcription arrives with no key. The recording says which piano keys were pressed and nothing at
all about how they should be spelled, so a black key is an F sharp or a G flat depending on a
decision nobody has made yet. Until someone makes it the page is written in C major, and every black
key prints its own accidental beside its notehead.

Measured on *Mr Blue Sky*, that costs **242 accidentals**. The piece reads as F major, which prints
one flat in the clef and lets a player read it once.

**This is a gap in the plan, not a task waiting further down it.** The word "key signature" does not
appear in `plan.md`, `checklist.md`, `decisions.md` or `PRD.md`. It went missing in P4.2: the control
lived on the Music Notation tab, which was one of the five tempo-based tabs retired there, and
nothing put it back because no phase was tracking it. The drawing package has drawn signatures since
long before this refactor, so nothing had to be built there.

David asked for it directly, so it is recorded here as its own task rather than folded into another.

## 1.2 What was built

**The frontend.** `RhythmPage` has a **Key signature** picker beside the sheet, listing all fifteen
signatures by both their major and their minor name with the count of sharps or flats, because a
reader who knows the piece is in D minor should not have to remember that D minor prints the same one
flat as F major. Beside it is a suggestion: `Try F major / D minor — 1 flat (242 fewer accidentals)`,
which is a button that applies it. When nothing would do better the line says so instead.

`TimeScoreView` takes the signature and passes it to the renderer, and asks the package's
`suggestKeySignature` what the notes themselves suggest. The count reported is measured with the same
spelling rule the page prints with, so it is the ink actually saved rather than a second opinion
about it.

**The backend.** `SavedRhythm` gains `keySignature`, optional. A key is part of the reading and not
of the recording, which is exactly what that file is for, so it belongs beside the anchor rather than
in a new store. It is optional because readings were already on disk without it, and a reading with
no key means C, which is what those readings were drawn in.

**The drawing package is unchanged.** It has taken a `keySignature` option all along.

Files: `aitu-frontend/src/api/timeScore.ts`, `src/api/index.ts`,
`src/components/time/TimeScoreView.tsx`, `src/pages/playground/RhythmPage.tsx`;
`aitu-backend/src/aitu_backend/schemas/rhythm.py`.

## 1.3 Decisions taken inside the task

The picker sets the key for the **whole piece**, which is what was asked for. The package supports a
key change part-way through, as a frame-keyed annotation, and the payload has nowhere to carry one.
Adding that means a second store and a second drawing gesture, and it is a separate piece of work.

The suggestion is offered and never applied by itself. A piece can genuinely be written in a key that
costs a few more accidentals, and a count is evidence rather than an answer. This is the same rule
the ladder follows: the app presents, the user decides.

## 1.4 Things I believed that turned out false

I expected the key to belong on the score payload, sent by the backend with the notes. It does not:
the payload is derived from `events.json` on every request and holds nothing a person chose, so a key
put there would be recomputed away on the next call. Everything a reader decides lives in
`rhythm.json`, and the key is one of those things.

## 1.5 Tests

`tests/test_saved_rhythm.py`: the round-trip check now carries a key and asserts it comes back, and a
new check asserts that a reading saved before the field existed still loads and reports no key.

Backend: 588 passing, 6 skipped, one failing. The failure is `test_api_smoke::test_scores_returns_a_list`,
which `plan.md` P4.8 records as pre-existing. Frontend: `tsc -b` and `eslint` clean.

Looked at in a browser, against the real recording. Writing the sheet in C shows the picker reading
`C major / A minor` and the line `Try F major / D minor — 1 flat (242 fewer accidentals)`. Pressing
it redraws with one flat on both clefs, visibly fewer accidentals through the piece, and the line
becomes `No other signature would print fewer accidentals than this one`. Saving the rhythm writes
`"keySignature": "F"` into `rhythm.json`, and reloading the tab comes back in F. No console errors.

## 1.6 Left open

A key change part-way through a piece. The package draws one; nothing stores one.
