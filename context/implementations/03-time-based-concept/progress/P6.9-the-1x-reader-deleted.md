# 1. P6.9 — the drawing package stops reading a 1.x file

Task: P6.9. Contract: §7, and §1's rows for `tempoBpm` and `granularity`.

## 1.1 Why this was needed

The package could open a matrix file written by the old pipeline. That reader was deliberately
forgiving, because a stored file might be in any of four shapes and might be missing a field: it
accepted `rMatrix` + `lMatrix`, `denseRMatrix` + `denseLMatrix`, a single `matrix` or a single
`denseMatrix`; it completed a missing tempo from the granularity code, or a missing frame length
from the tempo; and it split a one-hand matrix at middle C when the file carried no hand map, saying
so in the warnings.

Every one of those coped with a file the old pipeline might have written. Contract §7 kept the reader
for one release so stored pieces could still be opened while the migration ran. The migration ran on
2026-08-08 (P4.5), and the pipeline now writes one shape: two hands, already split, on a wall clock.
So the tolerance is dead code that can only be reached by a file that should be transcribed again.

The envelope header had the same problem one level up. It carried a `tempoBpm`, a `granularity` and
a `timeStepSeconds`, which said the same thing three times and could disagree with each other. The
frontend was already filling two of the three with invented values (`tempoBpm: 60`,
`granularity: "semicorchea"`) purely to satisfy the reader.

## 1.2 What was built

**The header is one field.** `MatrixEnvelopeMetadata` now carries `frameMs`, how many milliseconds
one column lasts, and `matrixProcessingStep`, which has one value, `'two-hands'`. `tempoBpm`,
`granularity`, `timeStepSeconds`, the `Granularity` type and the dense envelope's `rowTimestamps` are
deleted. `matrixProcessingStep` lost `'raw'`, `'collapsed'` and `'clean'`, which no longer exist.

**The reader reads one shape.** `parseMatrixEnvelope` requires `"schemaVersion": "2.0"`, `frameMs`
and the two hand matrices, and is strict about each: a field that is missing or the wrong shape is
named in the error rather than recovered from. The only thing still tolerated is a file with no
`frameMs`, which is read at the default 40 ms with a receipt in the warnings.

**A 1.x file is refused rather than converted**, which is what contract §7 says, and the message
explains why: a wall-clock matrix is built from the recorded onset times so that the notes can be
grouped and snapped again, this package does not have them, and guessing from the columns would
produce a page that looks right and is a different performance.

Gone with them: `EnvelopeSummary.handSplit`, `HandSplitMethod`, the hand-map reader, the pitch split,
the duplicate-cell and out-of-range recovery, and `resizeRowTimestamps` in `edit/matrix-edit.ts`,
which stretched a tempo map when frames were inserted.

`docs/api.md` §Loading a matrix file is rewritten. The editor artifact's loader note now describes
the one shape it reads.

## 1.3 Cross-repo change

`aimpromptu/aitu-frontend/src/components/time/TimeScoreView.tsx`. It built the envelope it hands to
the drawing package with an invented `tempoBpm: 60` and `granularity: "semicorchea"`, with a comment
saying they were there for the older reader. It now passes `frameMs` from the score payload and
nothing else about time. Staying inside `vexflow-v2` was not possible: deleting the fields makes the
frontend's object literal invalid, so the app would not compile.

The contract did not move. §1 already said `tempoBpm` and `granularity` were gone from the matrix.

## 1.4 Things I believed that turned out false

I believed the demo artifacts were the only place still building a 1.x envelope, so that the
frontend would be untouched. The frontend was building one too, and had been since P7.2, with the
invented values named in a comment. Nothing failed at runtime because nothing read them, which is
exactly why it survived four phases unnoticed.

I also believed `timeStepSeconds` was purely envelope metadata. It is also a renderer option, where
it is the clock and is correct, so a rename that treated the two as one thing turned fifty-two
renderer calls into nonsense before the compiler caught them.

## 1.5 Tests

`tests/load-envelope.test.ts` was rewritten. Ten of its thirteen checks tested tolerance that no
longer exists: the four payload shapes, the hand map, the pitch split, the duplicate cells, the
derived tempo. Six checks replaced them and cover the reader as it now is: the one shape read
whole, the same file read from its JSON text, the missing `frameMs` falling to 40 ms with a receipt,
a 1.x file refused with the reason, and five separate ways of being malformed each naming their own
field. The three windowing checks are unchanged apart from reading `frameMs`.

`tests/review-regressions.test.ts` lost the `rowTimestamps` renumbering check with the function.
Around forty test files had `tempoBpm`, `granularity` and `timeStepSeconds` removed from their
envelope fixtures.

Whole package: 42 files, 365 checks, none failing. `tsc -b`, `eslint`, `prettier`, `npm run build`
and `npm run build:deliverables` are clean, and `tsc -b` and `eslint` are clean in `aitu-frontend`.

Looked at in a browser, against the real recording rather than a fixture. The Rhythm tab draws the
peak plot with piles at 67, 120, 219, 337, 463, 674, 750 and 799 ms, which are the values the proof
of concept measured. Naming the 337 ms pile a negra reports `negra = 337 ms · ≈178 BPM` and writes a
staff of 2669 notes at 40 ms per column, with beamed runs, and no console errors.

## 1.6 Left open

P6.8, which is the documentation pass.
