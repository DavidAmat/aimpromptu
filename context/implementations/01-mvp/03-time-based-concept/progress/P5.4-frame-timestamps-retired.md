# 1. P5.4 — the clock stops accepting a timestamp per frame

Task: P5.4. Contract: §1, the row that reads `FrameClock.frameTimestamps` becomes *(unused)*.

## 1.1 Why this was needed

While a column was a note figure, the length of a column in seconds depended on the tempo where it
sat. A recording slows down and speeds up, so one scalar could not say when frame 500 began, and the
package accepted a measured second for every frame instead: `frameTimestamps`. Everything that turns
a frame into a moment (the ruler, the transport, the playhead) followed that array when it was
present.

A column is now a fixed slice of wall clock, 40 ms by default, and it is the same length everywhere
in the piece. The array can therefore only repeat the scalar. Keeping it means keeping a second
answer to a question that has one answer, and a second answer is the thing that eventually disagrees
with the first.

## 1.2 What was built

Deleted:

- `FrameClock`'s `frameTimestamps` option, its `starts` array, its `isUniform` flag, its
  `frameTimestamps()` method and the binary search that read the array.
- `shiftFrameTimestamps` in `src/time/frame-clock.ts`, which renumbered the array when frames were
  inserted or removed, and its export from `src/index.ts`.
- `GridNotationRendererOptions.frameTimestamps` and the rebuild of the clock after a structural edit.
- `ScorePlayerOptions.frameTimestamps`.
- `readFrameTimestamps` in `src/matrix/load-envelope.ts`, which read a file's `rowTimestamps`, and
  `LoadedEnvelope.frameTimestamps`.

Changed:

- `src/editor/grid-notation-editor.ts`: the three places that printed a different Time panel for a
  non-uniform clock now print the one answer. The panel itself belongs to P6.8.
- `docs/api.md` §Time.

`FrameClock` keeps its whole public surface apart from `isUniform`: `secondsForFrame` (still
fractional, so the playhead still moves inside a frame), `frameForSeconds`,
`frameForSecondsFractional`, `frameDurationSeconds`, `durationSeconds`. Every conversion still goes
through it, which is the property D-22 depends on.

## 1.3 Decisions taken inside the task

`isUniform` was deleted rather than left as a constant `true`. A flag that cannot be false invites a
reader to write a branch for the case that cannot happen.

`rowTimestamps` on the 1.x dense envelope was left alone. It is part of the 1.x envelope shape, so it
goes with P6.9 rather than here.

## 1.4 Things I believed that turned out false

I believed the package was green when I started. It was not. `npm run build:deliverables` followed by
`npm run test` failed one check in `tests/deliverables.test.ts`, and it failed before I changed
anything. The Epic 4 artifact asks the reader to press **narrow** and see the music wrap onto more
lines. D-33 made a beamed run 35 % tighter, so the same music now fits on one line at 360 px and
nothing wraps. The artifacts in `deliverables/` were last built on 2 August, before D-33, which is
why nobody saw it.

Measured on the Epic 4 score, beams on and off, as the number of lines the music takes:

| Width | Beams off | Beams on |
|---|---|---|
| 920 px | 1 | 1 |
| 440 px | 2 | 1 |
| 360 px | 2 | 1 |
| 300 px | 3 | 2 |
| 280 px | 3 | 2 |

The **narrow** button now asks for 280 px, so the artifact demonstrates what it says again. The
package's own spacing was not changed.

## 1.5 Tests

`tests/frame-clock.test.ts` was rewritten. The five cases that fed a timestamp array are gone: a
non-uniform clock cannot be built any more, so they were testing a constructor argument rather than
a behaviour. What replaced them pins that every frame lasts `timeStepSeconds`, that a fractional
frame still interpolates, that every frame boundary round-trips to its own frame at 40 ms, and that
the constructor still refuses a frame count or a step that is not a clock. The second half of the
file, which was "a score whose tempo is not constant", is now "a score read on the wall clock" and
checks that the ruler, the note schedule and the transport all read the same scalar.

`tests/review-regressions.test.ts` lost the `shiftFrameTimestamps` case with the function.
`tests/load-envelope.test.ts` lost the `rowTimestamps` case with the field.

Whole package: 43 files, 395 checks, none failing. `tsc -b`, `eslint`, `prettier` and
`npm run build` are clean, and `npm run build:deliverables` regenerates all eight artifacts.

Looked at in a browser: `deliverables/epic-04-beams-and-grouping.html` draws both staves with beamed
groups and reports no console errors.

## 1.6 Left open

The 1.x dense envelope still carries `rowTimestamps`, and `docs/integration.md` still describes
handing a new tempo map back to the renderer. Both belong to P6.9 and P6.8.
