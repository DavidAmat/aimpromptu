D-09, D-10, D-12, D-13, D-15, D-17, D-19 to D-21, D-23, D-24, D-27, D-28, D-31 as documented shapes.
Date: 2026-08-06. Status: done.

## 1. Why this comes first

The backend and the renderer are built at the same time, in repositories that cannot import from
each other. If each side invents its own field names, the two halves compile perfectly and fail to
meet. The models here are deliberately unused: they exist so both sides can be written against the
same names, and so a rename is a visible change in two files rather than a surprise at integration.

## 3. Decisions taken inside the task

**A separate `FigureName` enum, not an extension of `Granularity`.** The two vocabularies share
seven words, so reusing the enum looked attractive. They mean different things: `Granularity` names
the resolution of a column, which `contract.md` §1 removes from the grid, and `FigureName` names a
printed glyph, which has two dotted members that a column resolution can never have. Reusing one
enum would have made P4.4 impossible to finish, because deleting `Granularity` from the storage
layer would also delete the figure vocabulary.

**`TimeMatrixProcessingStep` is a new enum with two members.** The existing `MatrixProcessingStep`
still admits `collapsed` and `clean`, which the 2.0 envelope forbids. A separate enum means an
invalid step is rejected at the boundary instead of being caught later.

**`timeStepSeconds` is a computed property, not a stored field.** `contract.md` §1 calls it a derived
convenience and §2 leaves it out of the interface. A property satisfies both and cannot drift from
`frameMs`.

**The passage tiling rule is enforced, not just documented.** `contract.md` §4 says passages tile the
piece with no gaps and no overlaps. `TimeScorePayload` now rejects a payload where they do not,
because D-21 depends on it: a passage that does not own its frames cannot bound the effect of a
ladder change.

**The ladder validator checks completeness and positivity only.** It does not check that
`ms_by_figure[anchor_figure]` equals `anchor_ms`. That relationship belongs to the ladder builder in
P2.3, and asserting it here on floating-point values would have added a tolerance argument to a stub.

**`FIGURE_NEGRAS` is included.** The table of how long each figure is in negras is part of the closed
vocabulary rather than part of the fitting, so it sits with the enum. Building a ladder from it is
still P2.3's task and was not written.

## 4. Things I believed that turned out false

I expected `SparseCooMatrix` to need a 2.0 variant. It does not: `contract.md` §2 keeps the sparse
payload unchanged, and the cell meanings are the same, so the new envelope reuses the existing model
directly. That is worth knowing for P1.3, which does not have to touch the sparse encoding at all.

I also expected the envelope to need a single-hand `matrix` field like its 1.x predecessor. The
contract does not have one, so the model does not either. That gap is real and is recorded as I-02
in [`issues.md`](issues.md); it is not something P0.2 should decide.

## 5. Tests

`aitu-backend/tests/test_time_matrix_schema.py`, nine tests, all passing. They cover the things a
later phase could break without noticing:

1. The envelope carries no `tempoBpm` and no `granularity`, and one frame is 40 ms.
2. The envelope travels as camelCase, with the exact names the renderer reads.
3. Both hands must span the declared `frameCount`.
4. The figure vocabulary has nine members and dots only on `blanca` and `negra`.
5. A ladder must carry all nine figures.
6. A passage must end after it starts.
7. Passages must tile the piece, with three failing cases: a gap, an overlap, and short coverage.
8. A printed note keeps its camelCase field names, and `hand` refuses `single`.
9. The alignment window defaults to 20 ms, the same window as the chord grouping.

Nothing was deleted.

**How they were run.** This session works from a Linux virtual machine over the mounted folders, and
the backend's virtual environment is built for macOS, so `pytest` could not run in place. The
module and the test file were copied into a Linux container with pydantic 2.13.3 installed and run
there, which exercises the real model code. Please run `cd aitu-backend && pytest
tests/test_time_matrix_schema.py` on the Mac to confirm, and `make lint` for black, flake8 and mypy.
Line length was checked by hand against the 100-character limit.
