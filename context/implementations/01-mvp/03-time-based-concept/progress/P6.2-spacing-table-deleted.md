# 1. P6.2 — space on the page is time, not duration

Task: P6.2. Decisions: D-22, D-26, and the cost D-33 states.

## 1.1 Why this was needed

Engraving convention gives a long note more room than a short one, but not in proportion: a redonda
lasts sixteen times a semicorchea and is given about three times the room. The package carried that
convention as a table, `STAFF_SPACES_BY_BEATS`, and used it to decide how wide a column should be.

On a wall-clock page that rule is wrong twice. Distance between two onsets is the time between them,
so the width of a column is already decided by the clock and by what is drawn in it. And the figure a
note carries is a label the reader chose, so charging a column for its label would let renaming a
ladder change the geometry of the page for a reason that has nothing to do with what was played.

Frame widths have been measured from content since P5.2. The table was still exported and still fed
two helper functions, so it was reachable and could be picked up again by mistake.

## 1.2 What was built

Deleted from `src/notation/spacing.ts`:

- `STAFF_SPACES_BY_BEATS`, the seven-row engraved table.
- `staffSpacesForBeats`, which interpolated it in log2.
- `defaultPixelsPerFrame` and `pixelsPerFrameForMusic`, the two width helpers that read it.

`DEFAULT_PIXELS_PER_FRAME` stays, as the plain number 14.4. It is used only when a host supplies no
music to measure, and 14.4 is the value the table gave a negra, so nothing a host draws today moves.

`src/index.ts` stopped exporting the four deleted names. `docs/api.md` says what replaced them.

Nothing else in `spacing.ts` changed. `measureFrameWidths` already worked from noteheads, seconds
between them, accidentals, dots, flags and the tighter gap a beamed run gets under D-33.

## 1.3 Decisions taken inside the task

`MIN_ONSET_WIDTH_SPACES` was kept. It is not part of the engraved table: it says how much room a
notehead with an accidental in front of it needs, which is a fact about the glyphs and stays true.

## 1.4 Things I believed that turned out false

I believed a frame's width no longer depended on the printed figure at all, and it still does in one
place. `measureFrameWidths` adds room for a dot, and for a flag when beaming is off, and both come
from the figure. That is drawing rather than duration, because the glyph is genuinely wider, so it
stays. D-33 already records the consequence: renaming a passage moves the notes inside it.

## 1.5 Tests

`tests/engraving.test.ts` lost the three checks that asserted the table's own numbers, because there
is no table to assert. Two checks replaced them and pin the rule that took its place: two frames
carrying the same notehead come out the same width whether the note lasts eight frames or one, and a
frame nothing is drawn in stays narrow, which is what compresses a silence. The check on the closest
pair of onsets a piece contains was kept and now reads `MIN_ONSET_WIDTH_SPACES` directly.

Whole package: 43 files, 393 checks, none failing. The count fell by two because five checks were
removed and three added. `tsc -b`, `eslint`, `prettier` and `npm run build` are clean.

Looked at in a browser: `deliverables/epic-02-grid-staves-wrapping.html` and `deliverables/editor.html`
both draw with no console errors, and Epic 2 still reports two systems at 20 px per frame.
