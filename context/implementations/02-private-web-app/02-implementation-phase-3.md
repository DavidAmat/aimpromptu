# 2. Story 3.1: the folder and the tables

## 2.1 `.database/`

`paths.database_dir()` is `AITU_DATABASE_DIR` or `<repository>/.database`. On this machine
`.database` is a symbolic link to `/mnt/ssd2/aimpromptu/.database` (P-4), made once:
`mkdir -p /mnt/ssd2/aimpromptu/.database && ln -s … .database`. Compose mounts the host folder
(`${AITU_DATABASE_DIR:-./.database}`) at `/database` and sets `AITU_DATABASE_DIR=/database` inside;
mounting at a fixed path avoids a link that points outside the container. `make up` and
`make test-backend` make `./.database` first when nothing is there, because Docker would make a
missing mount source as root.

`db/database.py` opens the SQLite file on first use: it makes the folder, writes or checks `VERSION`
(layout `1`; another value stops the app with `LayoutVersionMismatch`), brings the tables to the
newest Alembic revision, and turns on WAL mode and foreign keys. Engines are kept per file, so each
test gets its own database. The app's start (`main.py`) opens it, makes the top folders and the
master user.

## 2.2 The tables

`db/models.py`, autogenerated into `db/migrations/versions/0001_initial.py` and reviewed, with the
fixed lists added to the revision (13 genres of section 15.3, 4 tag categories, the region
`worldwide`). Every table of section 8.6, plus four things the section needs but did not list:

- `parts` (id, project, position): a part must find its project (P-6);
- `song_genres`: the link of a song to its one or two genres;
- `external_key` on the public artists, albums and songs, for the import of Phase 12 to find the
  same row again (section 15.5, identity);
- `songs.default_version` (`hard`): what Default points at.

`projects.step` (the lowest step reached) is filled by the migration and by `db-reindex`; nothing
keeps it current at runtime yet, because nothing reads it before the Projects page of Phase 5.

**The master user** is made on the first start from `AITU_MASTER_USERNAME` (default `master`), with
no password: the login is Phase 4. `db/users.py::current_user_id()` is the one place that says
"every request acts as the master user"; Phase 4 replaces it with the user of the session.

# 3. Story 3.2: the bundle

## 3.1 What a part is now

`storage/locate.py` finds the project, the owner and the layer of a part in the `parts` and
`projects` tables, and keeps the answer in memory (a missing part is never kept, so a project made
by another process is found at once). `storage/paths.py` builds every path of a part from it:
`part_dir`, `part_notes_path`, `part_sheet_path`, `part_timeline_path`, `part_cache_dir`,
`staging_session_dir`, `history_version_dir`, `video_dir`. **A project made by this app has the id
of its first part**, so a project of one part has one uuid, and the uuid of every route of
implementation 08 is unchanged.

`audio/store.py` keeps its functions (`get`, `read_metadata`, `update`, `set_cuts`, `rename`,
`delete`, `create`, `save_original`) so the 20,000 lines that call it did not change. It now reads
and writes the bundle: `alias` is `project.json`'s `title`, the source fields are
`parts[].source`, `cuts` and `audioRevision` come from the timeline. `StoredAudio.directory` is the
part's cache folder (scratch clips land there), and `original_path` is the stored file.

## 3.2 `notes.pmn` version 2 (Task 3.2.1)

`pmn/notes_file.py`: the portable `.pmn` with the header of `events.json`, every note in the order
of the part (removed notes too), `removed` and `handGuessed` as id lists, and `outside` for a note
outside the 88 keys (none exists). The rest of the backend still works in the shape of
`events.json`: `pmn/events_file.read_payload` and `write_payload` convert at the file boundary, so no
reader of the notes changed. `portable.from_portable` reads version 2 as an export (the live notes
only).

**One change from the plan.** Section 8.3 said "the portable `.pmn.json` of implementation 08",
whose times have one decimal of a millisecond. The first trial of the migration refused the two
hand-made demo pieces (`11111111-…`, `22222222-…`): their note times have six decimals of a second.
`notes.pmn` therefore keeps up to three decimals (a microsecond) and reads seconds back with six,
and all 71,290 notes of the 37 pieces read back equal. The plan says so in section 8.3.

`sheet.json` is `rhythm.json` unchanged, with two optional fields for Phase 7 (`lyricsPool`,
`figuresFrom`).

## 3.3 The audio store and the timeline (Task 3.2.2)

`storage/audio_files.py`: `add_stream` (an upload, hashed while it is written), `add_file`,
`delete_unused` (only a file no `audio_refs` row names). `bundle.write_timeline` keeps
`audio_refs` exact (the parts' timelines and the history snapshots), and `delete_project` deletes
the files no other project uses.

`timeline.json` holds `audioRevision`, the files the part uses with their extension and length in
10 ms frames, and the segments. **Added to the plan's example:** the `audio` map with the frames, so
a cut that reaches the end of the file is still a cut without the database, and `toMs: null` for a
file not measured yet (between an upload and its normalization). `bundle.segments_for_cuts` and
`cuts_of` convert the cuts of implementation 08 both ways (tested on six shapes of cuts, the whole
file cut included). A part with no audio refuses a cut instead of losing it silently.

The cache is one folder per part, `cache/<partId>/` (the plan wrote `cache/<partId>-r<N>.flac`):
`normalized.wav`, `waveform.json`, `piece-r<N>.flac/.wav`, scratch clips. `store.get` writes
`normalized.wav` again from the stored file when it is missing, once the part was measured.

**Edits that make new audio.** The splice of a re-recorded passage and a passage put in (Epics 11
and 13) used to overwrite `original.wav`. They now store the new recording as a new file
(`store.replace_original`, which keeps the cuts and deletes the old file's joined audio and peaks),
and the history snapshot keeps the old file through its `timeline.json`. History snapshots no
longer copy any audio (`notes.pmn`, `sheet.json`, `timeline.json` only).

## 3.4 Every writer through `paths.py` (Task 3.2.3)

`pipeline.events_path` / `rhythm_path` / `needs_rederivation_path`, `editing/history.py`,
`storage/staging.py`, `audio/piece_audio.py`, `audio/ingest.py`, `editing/session.py` and the video
store now build their paths from `paths.py` and the store. The video of a part is
`tmp/<userId>/<partId>/video/`. `paths.data_dir()` (the old store) is read only by the migration and
by `paths.frame_examples_seed_dir()`.

## 3.5 Deleted (Task 3.2.4)

`api/library.py` (`/library`: playground, `.npz`, promotions, tags, playlists), `storage/repository.py`,
`promotion.py`, `browse.py`, `playlists.py`, `matrix_store.py`, `PianoMatrix.save_npz` / `load_npz`,
and their tests (`test_repository.py`, `test_library_browse.py`, `test_playlists.py`,
`test_storage_layout.py`, two `.npz` tests). Also the one-off migration of implementation 03
(`scripts/migrate_to_time_matrix.py`, `inventory_artifacts.py`, `test_migration.py`): it converted a
`matrices/` layout that cannot exist in `.database/`. A test checks that `/library/...` answers 404;

## 3.6 One route early: `POST /projects/{id}/duplicate`

The scripts that work on a temporary copy (`bench:sheet`, `time:flow`, `bench_pieces.py`, and the
rule that every script that clicks works on a copy) copied a piece folder by hand. A project is now
a bundle plus rows, so they need a server-side copy. `api/projects.py` has the one route Phase 5
would add anyway: a copy in the current user's Personal Vault with new ids, the same audio files
(no bytes copied), no history, staging or video. `check:flow`, `time:flow` and `bench:sheet` find a
piece through `GET /audio/`, copy it with this route, take Superestrella's audio from
`GET /audio/{id}/file?original=true`, and delete through `DELETE /audio/{id}`. None of them reads
the disk any more.

# 4. Story 3.3: the migration

## 4.1 The script

`scripts/migrate/to_database.py` follows section 8.9: the master user; for each
`data/audio/<uuid>/` a project of one part with the same id, the audio file into the store, the
cuts into the timeline, `events.json` into `notes.pmn` **checked note by note** (ids, keys, times,
hands, flags, the header, the length and the title must read back equal, or the piece fails),
`rhythm.json` into `sheet.json` unchanged, the cache files, `history/vN/` with a timeline instead of
the audio, the video into `tmp/`; the seed list's pieces into the master user's Private Library
with a private song, a private artist and the version `original`; `frame-examples/` into Lab.

Three choices the plan did not spell out:

- **The two pieces without notes are moved too** (Perfect, whose video is calibrated, and Chopin
  Prelude). The plan said "each piece with notes"; moving them leaves nothing behind.
- **The new files keep the old modification times**, and `project.json`'s `updatedAt` is the newest
  time of the old folder. The first real run showed every project as "changed a few minutes ago" on
  the Projects page; the folder was emptied and the migration run again with this fix.
- **A failed piece leaves nothing**: its partial project is deleted, and the report names it.

It never writes into `data/` (a test compares every file time before and after; on the real run the
size and name of every file of `data/` were the same before and after), and it skips a piece whose
project exists, so a second run changes nothing (tested, and run twice on the trial folder).

## 4.3 Backup, restore, check, reindex (Task 3.3.3)

`aitu_backend/db/tools.py`, run on the host by the Makefile because they need `tar` with zstd and the
image has no zstd. `make db-backup` took about 2.6 s and wrote 1.08 GB. Two defects were found by
testing it and fixed:

- The first archive had **no database file**: the `--exclude` that skips the live
  `aitu.sqlite` also skipped the consistent copy, which had the same name. The copy now comes from
  its own folder. A restore into a new folder then passed `db-check --hashes` with 39 projects and
  the same files as the source.
- tar answers 1 when the app writes a file during the copy (a cache file). That is now a warning
  and the backup is kept; any other error deletes the archive.

`db-reindex` is tested on the fixture: with every project row deleted, it writes them again from
the bundles (owner, layer, parts, step) and `db-check` is clean.

One backup is at the root of the repository, `.database-20261006-140014.tar.zst` (1.08 GB,
gitignored), taken right after the migration.

# 5. The tests

Every test has its own `.database/` (plan section 22): `tests/conftest.py` migrates one database per
run and copies it into each test that opens one, and points `AITU_DATABASE_DIR` at a temporary
folder before any test module loads.

**A trap found on the way.** A `skipif` of `test_video_examples.py` read the Lab records while the
tests were being collected, before any fixture: it read the default `.database/` and made a folder
in it. With the records moved, those five tests would have been skipped silently, and with the new
mount the collection would have written into the real database. The `skipif` now reads the
committed records, a module fixture copies them into each test's Lab, and the environment variable
is set before collection. All 11 tests of the file run and pass, none skipped.

New tests: `test_database.py` (9: the folder, `VERSION`, every table, the fixed lists, WAL and
foreign keys, the master user, finding a part), `test_bundle.py` (19: cuts and segments both ways,
the bundle and its rows, one stored file for the same bytes, duplicate, delete keeps a shared file,
a lost `normalized.wav`, a new file for the history, the duplicate route), `test_notes_file.py` (6),
`test_to_database.py` (8). About thirty older tests were moved to the new paths (`notes.pmn`,
`sheet.json`, a part made before its video is written, a real audio file under a cut).

# 8. Open points

- **`aitu-backend/data/` can be deleted by the user** after checking the migrated projects in the
  browser (the human step of the plan). Nothing reads it except the migration and the committed
  Lab records (`data/frame-examples/*.json`, tracked by git), which stay.
- **`projects.step` is not kept current** at runtime (section 2.2): Phase 5's list should update it
  when a part's status changes, or compute it.
- **The joined audio and a splice with cuts.** A splice on a part that has cuts keeps the cuts in
  frames of the old file, as before Phase 3. A passage put in moves the frames after it, so its cuts
  may then cover the wrong range. This was already true before and nothing in the app makes it
  happen (the Record panel works on the piece's time); Phase 9 replaces these panels.
- **Six private songs have no artist**, because the seed list names none on those lines. Phase 6's
  pages will show them as songs without an artist, which the user can fill in.

# 9. Learnings for later phases

- **Collection-time code reaches the default folder.** A `skipif` or a module-level client runs
  before any fixture; anything it reads or writes must not depend on a per-test environment.
- **Exclude patterns in tar match every member**, not only those of the first `-C` folder.
- **Keep file times in a migration** when the app shows them ("when it changed").
- **`uv sync` without the extras removes them** from the local `.venv`. Use
  `uv sync --extra transcription --extra transkun --extra muscriptor --group dev`, or
  `uv run --no-sync`.
- **The `make db-*` commands run on the host** (zstd); the app and the tests run in the container.
