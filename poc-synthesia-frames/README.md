# PoC — reading a Synthesia frame

**Status:** research spike, Phase 1 of
[`04-synthesia-to-notes`](../context/implementations/04-synthesia-to-notes/04-plan.md).
Nothing here is wired into the app, imports the app, or writes anywhere the app
reads. It reads the example screenshots and one video downloaded by hand, and it
produces pictures and tables.

The conclusions are in [`RESULTS.md`](RESULTS.md) and, for the next agent, in
[`04-phase-1-implementation.md`](../context/implementations/04-synthesia-to-notes/04-phase-1-implementation.md).

---

## The question

A Synthesia video draws every note as a rectangle falling onto a keyboard. The
notes are on the screen on purpose, so we should be able to read them instead of
guessing them from the sound. Phase 1 asks how: which computer vision primitives
find the falling rectangles, on the whole range of ways these videos draw them,
and what every threshold should be.

## What is in here

```text
scripts/
  common.py              loading, the working resolution, the piano overlay geometry
  find_keyboard.py       find the keyboard without the user, for the spike's own use
  overlay.py             draw a calibration on a picture
  zoom.py                a zoomed crop of that, to check the key borders by eye
  run_calibrate.py       run the finder over every example
  measure_uniformity.py  is the white key width the same across the picture?
  measure_halo.py        how far above the upper line does the light reach?
  catalogue.py           the measurable half of the casuistry catalogue
  label_sheet.py         draw the band with the lanes and the MIDI numbers, to read by hand
  detectors.py           the five candidates, sharing one run extraction
  run_detectors.py       run all five on nine examples, draw what each saw
  score.py               score a detector against the hand read ground truth
  shape_quality.py       does a run look like a note? width and midpoint, high in the roll
  scroll_speed.py        the background plate and the scroll speed, on a real video
  plate_test.py          the real plate against the single screenshot stand-in
  stitch.py              stack the sampled frames into one long roll
  testvid.py             the 90 second test video: frames, plate, calibration
  measure_gaps.py        how big is the gap between two rectangles stacked on one key?
  measure_valleys.py     how deep is a border when it does not break the run?
  roll_top.py            where the roll starts and where the strike light begins, from motion
  continuity.py          does the detector say the same thing twice about one rectangle?
  ode_momentum.py        the momentum rule on three frames: a rectangle falls, a letter does not
  export_example_ui.py   one example screenshot, for the inspection page
  export_ode_ui.py       the three Ode to Vivian frames and their verdicts, for the page
  export_ui.py           the frames and the detection, for the inspection page
data/
  calibrations.json      one piano overlay per example, from find_keyboard
  ground_truth.json      the onsets and sustains read by hand on two examples
  video/                 the downloaded videos, their sampled frames, their plates  (gitignored)
                         test.mp4 is 90 s of pgLt4WmPMYQ, sampled into frames_test/
out/                     only run_log.txt and stitch/ are committed; the rest is
                         regenerated by the commands below
  run_log.txt            every measurement in one file
  thumbs/                the 21 examples, small enough to look at
  calibration/           the overlay drawn on each example
  labels/                the band with the lanes and the MIDI numbers
  detectors/             what each of the five candidates saw
  stitch/roll.jpg        ten seconds of the video rebuilt as one piano roll
  ui/                    the five frames and detection.json behind the inspection page
```

## Running it

Everything runs on the backend's interpreter, which already has numpy, scipy and
pillow. There is no new dependency.

```bash
cd aitu-backend
uv run python -c "import sys; sys.path.insert(0,'../poc-synthesia-frames/scripts'); \
  import run_calibrate; run_calibrate.main()"
```

and the same shape for `run_detectors.main()`, `score.board()`,
`measure_halo.main()`, `measure_uniformity.main()`, `catalogue.main()` and
`stitch.measure(30)`.

The video steps need the video first. It is not in the repository; it is one
download by hand, of a piece the audio library already has:

```bash
cd aitu-backend
uv run python -m yt_dlp \
  -f "bestvideo[height<=720][ext=mp4]+bestaudio[ext=m4a]/best[height<=720]" \
  -o "../poc-synthesia-frames/data/video/shut-up-and-dance.%(ext)s" \
  --no-playlist "https://www.youtube.com/watch?v=Zil8XOMgBQU"
cd ../poc-synthesia-frames/data/video
mkdir -p frames && ffmpeg -v error -i shut-up-and-dance.mp4 -vf fps=10 -q:v 3 frames/f%06d.jpg
```

Then `scroll_speed.main()`, which also writes the background plate, and after it
`plate_test.main()` and `stitch.measure(30)`.


## The test video

`test.mp4` is 90 seconds of [pgLt4WmPMYQ](https://www.youtube.com/watch?v=pgLt4WmPMYQ),
the example where the left hand plays repeated notes and the rectangles touch.
It is what `measure_gaps.py` and `export_ui.py` read.

```bash
cd aitu-backend
uv run python -m yt_dlp -f "bestvideo[height<=720]+bestaudio/best[height<=720]" \
  -o "../poc-synthesia-frames/data/video/src.%(ext)s" --no-playlist \
  "https://www.youtube.com/watch?v=pgLt4WmPMYQ"
cd ../poc-synthesia-frames/data/video
ffmpeg -v error -y -ss 0 -t 90 -i src.mkv -c:v libx264 -crf 18 -preset veryfast -c:a aac test.mp4
rm src.mkv && mkdir -p frames_test
ffmpeg -v error -i test.mp4 -vf fps=10 -q:v 3 frames_test/f%06d.jpg
```
